BG/Q High Level Control System
Terminology and Naming Conventions

Overview

Commonly used terms and naming conventions within the HLCS software stack are described here.

Deprecated Terms

To clear up confusion about some commonly used terms in previous BG/L and BG/P software releases, the BG/Q HLCS stack has deprecated a few terms. They are called out in this list below. It's important to note that this effort is focused on external interfaces, and not internal cases where the old term is not exposed.

terminology

BGWS

The Blue Gene Web Services, provides services for the Navigator.

block

collection of nodes wired together such that they can communicate over a torus to their neighbors. Replaces the term partition. Partition as a verb is still accurate

compute node

a single node on a node board.

job

logical representation of a single binary running on an arbitrary number of compute nodes

I/O node

node used for I/O capabilities to file systems and external networks

midplane

16 node boards populate a midplane.

MMCS

midplane management control system, the heart of the HLCS software stack. Provides services for block creation, allocation, and booting. Also provides RAS handling facilities and environmental polling.

Navigator

web based Graphical User Interface (GUI) to the HLCS.

node board

32 compute nodes populate a node board. Replaces the term node card.

Compute Rack

Two midplanes populate a compute rack.

RAS

Reliability, Availability, and Serviceability

Real-time

Real-time notification API for job, block, and hardware state and status transitions.

runjob

job submission interface, replaces mpirun, submit, and mpiexec

scheduler

A higher level component that creates and allocates blocks using APIs provided by the HLCS to submit jobs in its queue.

Scheduler API's

API for job schedulers to use, replaces Bridge and Allocator API's.
